# Programmatic AI Lab

A local research instrument asking whether **a learned programming language reduces search on unseen tasks after charging for discovery**. The default dashboard compares a fixed scalar DSL, a learned library, and task-conditioned neural search priors. The off-road simulator is a separate control baseline with an engineered DSL. Independent implementation; not Argos's code or a reproduction of an undisclosed algorithm.

## Live 3D synthesis race

Open [Unseen challenge](http://localhost:5180/#challenge), then **Generate unseen challenge**. Both trucks wait while independent workers synthesize programs for the freshly sealed terrain. Each successful controller immediately drives its truck. Use **Run 10 sealed challenges**, **Remove primitives & rerun**, or **Export audit** to inspect repeated outcomes.

The DSL and neural prior are frozen before terrain generation. Both sides receive identical tasks, search seeds and evaluation caps. The current off-road library contains **zero accepted learned primitives**, so the race is expected to tie; it does not yet validate a language-learning advantage. The UI reports failures and ties without selecting favorable seeds. See [the protocol](OFFROAD_RESEARCH.md#live-unseen-synthesis-race).

The hill stability model now checks sustained loss of wheel support rather than an immediate fixed angle cutoff. Old results are preserved under `output/offroad-v1/`; the current reference and benchmark use `offroad-support-v2`. V2 reaches 78/108 destinations for unguided evolution and 72/108 with the neural prior, with no accepted DSL edits in either arm.

## Start here: language research

The default **Language research** tab shows four solve-rate curves, conditional and matched-solve effort, full discovery cost, projected break-even, actual batch cost, learned definitions, rejected edits, multi-seed robustness, structural task generalization, diagnostics and frozen-library ablations. It separates prior-only improvements from improvements attributable to the language. Research gates stay unproven when evidence is missing.

`src/dsl/` implements two rounds of program synthesis, abstraction mining/compression, short synthesis races, larger multi-seed races, independent confirmation, and neural-prior learning. The full protocol uses **500 training + 100 development/confirmation + 200 final tasks**, with three inner seeds and **20 predeclared meta-seeds (0–18 and 42)**. The fixed base algebra contains `add/sub/mul/min/max/neg`; invented functions are bounded compositions, not new semantics or types. Neural priors use successful programs and executed synthetic “dream” examples. Final targets supply I/O only and never influence training or library selection.

**Measured result:** no library edit passed confirmation in any of the 20 runs. Fixed and learned DSLs tie exactly: **589/12,000 uniform-search solves** and **692/12,000 prior-guided solves**. The 12,000 trials per arm repeat the same 200 tasks; they are not 12,000 independent functions. Discovery cost totals **64,578,627 candidate evaluations**. There is no demonstrated library benefit or library-cost amortization. This protocol is a falsifiable negative result, not a success claim.

Read [LIBRARY_RESEARCH.md](LIBRARY_RESEARCH.md) for the frozen protocol, acceptance objective, task splits, leakage controls, costs and limitations. Every result and program is exported under `output/library/`. The runner uses two independent processes by default (`LIBRARY_JOBS=1` for sequential timings) and supports `--resume` for an unchanged protocol. Concurrent wall times depend on machine workload.

`library:surrogate` trains a small linear DSL-edit value model on meta-seeds 0–15 and evaluates ranking on seeds 16, 17, 18 and 42. It compares against compression and expected random selection **only among already-screened finalists**. The 120 labels and model are saved. This is an offline, selection-biased ranking probe; it does not demonstrate saved outer-search evaluations. A cost-saving surrogate experiment must evaluate held-out selection policies prospectively.

## Control baseline: off-road autonomy

The **Control baseline** tab contains a real-time Three.js truck simulation over procedurally generated woodland, quarry and ridge height fields. There is no road, centreline or precomputed route: the controller gets a destination and must steer through the terrain. The flat-road experiment remains available as **Road baseline**. No scalar-language transfer to these controllers has been established.

The simulator supplies 104 observation values: five 19-direction vectors (goal alignment, obstacle clearance, slope, roughness, traction) and nine scalar state/constants. Terrain sensing uses exact simulated geometry. A typed Cartesian program combines vectors, selects a direction using an `argmax` primitive, and returns steering plus signed acceleration. The initial vector/scalar/angle type system, direction-selection semantics and observations are explicit engineering choices, not discovered perception.

`src/offroad/search.ts` implements mutation (including connected expression growth), type-compatible crossover, elitism, and epsilon-lexicase parent selection across terrain cases. A masked neural prior learns operator and operand choices with REINFORCE from partial-graph summaries, operand roles and requested value types. The graph summary is not a full semantic encoding of every partial program. Programs alone produce vehicle commands; collision and terrain-stability tests terminate unsafe episodes rather than choosing corrective actions.

At generations 20 and 40, the outer loop mines typed two-operation compositions from active programs. It tests each grammar with fresh synthesis on three **development** terrains and two optimizer seeds. Acceptance requires a mean fitness improvement above 0.5 and use of the proposed primitive by both development winners. These are empirical checks, not a proof that an abstraction is generally useful. Rejected proposals remain visible.

The vehicle includes terrain heights under four wheel-contact probes, pitch/roll, gravity along slopes, traction-limited acceleration/yaw, steering lag, drag, slip, footprint collisions and clearance/stability termination. Rendering interpolates fixed physics steps and smooths the camera. This is a quasi-static generic pickup model: no calibrated Raptor parameters, dynamic suspension, tire deformation, deformable soil or real-world validation. Public Raptor and Baja RC references motivated the task; see [OFFROAD_RESEARCH.md](OFFROAD_RESEARCH.md).

Use **Train off-road policy** for a fresh local run, select older checkpoints, switch terrain or camera, display scans, inject a rock, or take manual control using WASD / arrows. Replay is a frozen policy, not online learning. Injected rocks affect only the current replay and are removed on reset. **Test 36 unseen terrains** evaluates the selected frozen program on separate terrain seeds.

`npm run offroad:benchmark` runs the full 2×2 comparison (neural guidance on/off × DSL evolution on/off) across optimizer seeds `0, 7, 42`. Each arm receives the same 31,374 main-search rollouts. DSL discovery overhead is separately charged; this is **not** an equal-total-compute comparison. Every arm uses the same 36 held-out terrains. Clearance-sensor ablation reruns the policies with obstacles still present but reported clearance set to maximum. Full programs, per-family outcomes, ablations and proposals are saved under `output/offroad/`, `output/offroad-benchmark.json` and `public/offroad-benchmark.json`.

The reference run and benchmark are reproducible engine outputs. The benchmark is small and the three seeds share the same test suite. See its measured outcomes in the UI and [OFFROAD_RESEARCH.md](OFFROAD_RESEARCH.md); no superiority or sim-to-real claim follows merely from having a working simulator.

## Additional experiment: road driving

The **Self-driving** tab runs an actual vehicle controller in a Three.js closed-course simulator. Each policy reads eleven state-vector observations and directly outputs steering and signed acceleration (split into throttle and brake). The renderer and training evaluator call the same physics and program interpreter. No prerecorded trajectory, route-following override, or collision-avoidance override drives the car.

Press **Train driving policy** to run neural-guided evolutionary search locally. Inspect earlier generations, switch among sweeping roads, tight turns and obstacle courses, change the camera, drop obstacles, or take manual control with WASD / arrow keys. The separate unseen-road evaluation freezes the selected controller and tests 24 layouts. Export preserves the actual program graph and macro definitions.

```sh
npm run driving:reference
```

`src/driving/search.ts` evolves acyclic graphs with two outputs. Mutation changes operators, connections, constants and outputs; crossover and fresh neural proposals introduce candidates. The neural prior learns operator probabilities from rollout rewards. Fitness rewards route progress, completion, speed and centering, with small steering-change and program-size penalties. Every candidate executes in the vehicle simulator.

The outer DSL loop mines two-operation compositions from driving programs at generations 15 and 30. Each proposed grammar receives a fresh, equal-budget search on four development roads, compared with the incumbent grammar. Acceptance requires both better development fitness and actual use of the new operator in the winning program. This is a narrow, noisy heuristic for reusable abstractions, not open-ended language invention.

The seed-42 reference improves from **4/8 to 7/8 training roads finished**, with fitness **54.74 → 88.63**. On 24 unseen layouts it finishes **8/8 sweeping roads, 3/8 switchbacks and 2/8 obstacle courses**. Its final program uses lookahead-heading error for steering and a crude speed-error expression for acceleration; it ignores obstacle ranges. Both proposed macros are rejected because the improved development winners do not actually use them. This run demonstrates learned vehicle control, but does not demonstrate a benefit from DSL discovery.

The supplied observations already encode route direction and lookahead geometry. Perception, route planning and these features are engineered. Dynamics use a kinematic bicycle model with drag, steering rate limits, a grip-based yaw limit, substeps, vehicle-footprint collisions and road-departure termination. There is no traffic, camera perception, tire-slip model or real-world validation. The current driver fails visibly on harder roads.

## Additional experiment: evolve a scalar language

`src/engine/language.ts` implements two outer rounds of bounded, compositional grammar induction:

1. Genetic program synthesis on six induction tasks, using scalar inputs, arithmetic primitives, and constants.
2. Mine parameterized subexpressions from successful programs. Filter constants, identity functions, and sampled behavioral duplicates.
3. Propose one new macro at a time, evaluate every proposed language with fresh synthesis on three separate development tasks, and accept the best improvement.
4. Freeze the resulting language. Compare it with the base language on three held-out tasks × three paired optimizer seeds. Target functions are accessible to the fitness oracle; target syntax never enters the search.

Both final arms receive 669 candidate evaluations per trial, identical input examples, the same optimizer seeds, a 25-node syntax bound and a 60-node expanded bound. Candidate counts are equal; CPU costs are not necessarily equal. The discovered language can express compositions more compactly, which is the intended treatment. Each learned macro expands into its original expression.

Task partition:

| Induction                                                              | Development (grammar selection)                                       | Held-out final comparison                                      |
| ---------------------------------------------------------------------- | --------------------------------------------------------------------- | -------------------------------------------------------------- |
| Positive component; positive difference; magnitude of x/y; bounded x/y | Sum of positive components; sum of magnitudes; sum of bounded signals | Magnitude of a difference; positive part of a sum; bounded sum |

Fitness is mean absolute error on 25 input examples. Final correctness requires error below `1e-8` on these examples and 65 validation inputs (60 fresh samples plus five boundary cases). Development score is `2 * solved + 1/(1+validation_MAE) - 0.001 * syntax_nodes`, averaged over six searches. All induction and grammar-selection candidate evaluations are charged to discovery overhead. Proposal mining and other overhead are included in elapsed wall time, not candidate counts.

Seed 42's shipped run discovers `fn_1(a) = max(a, 0)`, with 7/9 held-out solves versus 5/9 for the base DSL, at 59,256 extra discovery evaluations. This is one small, designed task suite, not evidence of general superiority. Changing the seed can eliminate or reverse the improvement. Non-selected proposals and exact final expressions/errors remain inspectable.

The five-seed sanity check (`0, 1, 2, 3, 42`) yields 31/45 evolved-language solves versus 26/45 fixed-language solves. Seed 1 regresses from 7/9 to 6/9; seed 0 accepts no macros and ties at 4/9. Full counts and definitions are in `output/dsl-benchmark.json`. These trials share a small task family and should not be treated as independent evidence of broad generalization. See `RESEARCH_NOTES.md` for the interpretation and remaining gaps.

**Limits:** This mines macros in a preselected scalar algebra. It does not invent new semantics, types, perception primitives, recursion, or control flow. It does not implement a DreamCoder-style wake/sleep system, an open-ended self-evolving DSL, or Argos's undisclosed search algorithm. Behavioral signatures and validation samples are empirical checks, not proofs. The task family is intentionally related; broader domains and more seeds are needed. Grammar discovery costs much more than the nine final comparisons, so this run does not establish net compute savings.

## Additional experiment: grid navigation in a fixed DSL

`src/engine/search.ts` evolves Cartesian-style acyclic program graphs for grid navigation. Active nodes alone execute. Elitism, mutation, crossover, and fresh neural proposals improve policies evaluated over a fixed set of seeded warehouse/terrain worlds.

`src/engine/neural.ts` contains a real one-hidden-layer neural operator prior, updated with REINFORCE and a batch-mean reward baseline. Its inputs are gene position and the previous operator. Graph edges and constants are sampled separately; the prior is not a partial-program reasoning or value-search system.

The explicit scaffold supplies goal progress, visit memory, momentum, local clearance, legal-action filtering, and a fixed `argmax` controller. The program only learns the score expression. This makes navigation tractable but is not learned perception, memory, safety, or general control structure. BFS is used solely to reject unsolvable worlds and compute path efficiency; it never chooses the robot's action.

Successful episodes receive `70 + 30 * shortest_path / actual_steps`. Failures receive smaller progress/exploration rewards. Fitness subtracts 0.25 points per active graph node. Held-out transfer uses 24 new seeds per family, with narrow-passage worlds excluded from training. All evaluation seeds exceed the supported training-seed range. The Python export is standalone and trajectory-equivalent to the TypeScript interpreter.

## Why the language experiments are separate

Optimizing a controller in a carefully engineered language sidesteps the question of how the language is obtained. The language-discovery experiment addresses one narrow, testable slice of that question. It exposes the tradeoffs: useful representation bias versus a larger branching factor, compression versus search improvement, development-task overfitting, and the cost of discovering a grammar before it can be amortized across future tasks.

The original PDF is available locally at `/argos-paper.pdf`. No part of this app establishes physical deployment readiness, formal behavioral guarantees, or state-of-the-art research results.
